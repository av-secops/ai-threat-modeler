# Aegis Threat 2.3.2

## Products and releases

- Start from a product catalog, with unique product and release names.
- Model a complete release or separate applications within it. Add another
  application without overwriting earlier models.
- View creation dates, application scope, draft/report status and last modeled
  dates in the release lists.
- Save prepared drafts before navigating back, reopen existing reports, and
  compare report revisions across compatible releases.
- Keep immutable report history, with conflict handling for stale shared drafts.
- Keep Back and add-model controls accessible on desktop and mobile.

## Analysis and review

- Track declared source issues and their dispositions in the report.
- Check evidence, scope and control state before publishing confirmed findings.
- Reconcile architecture diagrams with the canonical model and its boundaries.
- Assess explicit business-workflow controls and a bounded set of AWS IAM policy
  interactions, leaving unsupported conditions unknown.
- Validate evidence-bound SLM proposals and expand executable knowledge rules.
- Show issue and assurance evidence alongside the risk register.
- Persist local analysis jobs and their results for recovery after interruption.

## Updating

Install frontend dependencies with `npm ci` and Python dependencies with
`pip install -r requirements.txt` in your virtual environment. Windows users can
run `start.ps1 -InstallDependencies` instead. Stop an existing launcher-managed
instance with `start.ps1 -Stop` before starting the new version.

Back up `backend/data/workspaces.sqlite3` before updating an existing workspace.
Stop the app first or use SQLite's online backup API. The schema update preserves
saved workspaces and derives older release dates from audit records when present.
Missing historical dates remain unknown.

The product registry and job queue use Python's standard-library SQLite support;
no extra runtime package was added for them. Optional GPU training stays in a
separate requirements manifest and is not needed to run the application.

## Scope

This release is an assisted technical review tool. A confirmed finding is backed
by input evidence, not a live test of a deployed system. Roles apply across an
installation; per-product tenant isolation, SSO and distributed job scheduling
are not included. Local databases, reviewer input and newly generated model
caches are excluded from this update.
